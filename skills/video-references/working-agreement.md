# Working agreement

The contract every expert in this pack shares. The director enforces it.

## 1. State lives in `.video/`, never in the conversation

All handovers are files, so any expert can be re-run alone and a returning
user (or a new session) can see exactly where things stand.

```
.video/
  brief.md           discovery: the answers, in the format below
  sources.md         every link given or found, and each fact used, with its URL
  product.md         app-tester: what the product is, flows, screens, claims
  captures/          app-tester: NN-slug.jpg screenshots (+ optional .webm clips)
    manifest.json    one entry per capture (see app-tester)
  storyboard.md      storyboard: scene table + per-scene copy
  theme.json         asset-builder: resolved style tokens (colors, fonts, radii)
  assets/            asset-builder: icons/, logos/, images/, generated/
    assets.json      what each asset is and where it came from (licence)
  audio/
    music.wav        sound
    sfx/*.wav        sound
    cues.json        sound: sfx timeline (frame, file, gain)
    vo/*.mp3|wav     voiceover: one file per scene line
    vo.json          voiceover: durations + word timings
    mix.wav          sound: the final mix the editor muxes in
  captions.json      voiceover: caption pages for the editor
  project/           editor: the Remotion project (copied from the template)
  stills/            editor: checked frames
  reviews/round-N.md critic
  out/               final.mp4, draft.mp4, poster.jpg, captions.srt, notes.md
  log.md             one line per decision: who, what, why
```

Append to `log.md`; never rewrite another expert's file without saying so in
the log.

## 2. `brief.md` format

```markdown
---
title: Grit in 60 seconds
type: product-demo        # explainer | product-demo | feature-launch | tutorial | promo | social-short
audience: beginner developers
goal: viewer installs Grit and builds a first resource
length_s: 60
format: 16:9              # 16:9 | 9:16 | 1:1 | 4:5
fps: 30
style: mono               # mono | brand | playful | bold | custom
structure: q-and-a        # q-and-a | problem-solution | walkthrough | feature-tour | story
music: generate:lofi      # none | generate:<mood> | file:<path>
voice: captions-only      # none | captions-only | tts:elevenlabs | tts:openai | user-audio:<path>
cta: gritframework.dev
source:
  app_url: https://example.com
  login: required         # none | required | provided
  repo: https://github.com/owner/repo
  docs: [https://...]
must_show: [install command, generate resource, admin panel]
must_avoid: [pricing, unreleased features]
brand: {logo: assets/logo.svg, colors: ["#000", "#fff"], font: Geist}
---

Free-text notes from the interview: the story in the user's words.
```

## 3. Defaults when nobody can answer

| Field | Default |
|---|---|
| length | 30 s for social, 60 s for demos/explainers |
| format | 16:9 1920×1080 at 30 fps |
| style | mono (Vercel/Resend) |
| structure | q-and-a for beginners, walkthrough for existing users |
| music | generate:lofi at −20 LUFS under everything |
| voice | captions-only |
| critic | 2 rounds max |

## 4. Rules nobody breaks

1. **Truth on screen.** Commands, code, file names, numbers and claims come
   from a source in `sources.md` (docs, the repo, a capture). Anything we made
   up to illustrate (summary output lines, mock data, a mock-up of a UI we
   could not capture) is allowed only if `notes.md` says so. Never invent a
   feature, a price, a benchmark or a testimonial.
2. **Credentials are the user's, used only where they said.** Demo logins
   go in environment variables or the browser tool's credential flow, never
   in files, logs, storyboards, commit history or on screen. Blur or replace
   real emails, names, tokens and API keys in captures before they reach the
   editor. Prefer a demo account; if the only login is a real production
   admin, say so and ask before using it.
3. **One idea per screen.** If a scene needs two ideas, it is two scenes.
4. **Readable means readable at the target size.** Minimum sizes and reading
   times are in `design-rules.md`; the critic measures against them.
5. **Look before you render.** The editor renders stills at the busiest
   moments and looks at them before any full render. A full render is
   expensive; aim for one draft and one final.
6. **Licences.** Music and SFX are generated by `video-sound` unless the
   user supplies a file. Icons come from open-licence sets (Lucide, ISC;
   Simple Icons, CC0, for technology logos used nominatively). No stock
   photos of real people, no copyrighted characters, no third-party UI shown
   as if it were the product.
7. **Ask with the ask tool, with real options.** Open questions only when
   the answer cannot be a choice (the idea itself, a URL).
